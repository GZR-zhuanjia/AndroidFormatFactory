# 代码评审与设备验证

评审日期：2026-10-28。评审范围为当前 Android Kotlin 应用的转换引擎、前台服务、SAF 文件选择/保存、应用内历史及 Compose 界面生命周期。

静态评审不等同于设备验证。本文将源码确认的行为、已编写的自动化用例和仍需实际运行的检查分开记录；尚未执行的用例不能视为通过。

## 核心静态检查结果

- 以实际轨道元数据识别视频/音频，不凭文件扩展名或 `audio/mp4`、`video/mp4` 等容器 MIME 推断。音频模式允许选择视频并提取声音；没有音轨时给出明确错误。
- 视频模式只要求视频轨道。Media3 的 `forceAudioTrack` 保持默认 `false`，因此无音轨视频可输出无音轨 MP4；此结论已对照本地 Media3 1.6.1 源码，仍应通过设备用例确认。
- 请求的音视频码率会使 Media3 的 `audioNeedsEncoding` / `videoNeedsEncoding` 返回 `true`，不会被同编码格式的直接封装路径绕过。
- 转换由非导出的前台服务承接；单个进程内只允许一个活动转换。成功前检查取消，未完成文件不会加入成功历史。
- 输入通过系统文件选择器获取；输出先写入应用私有临时目录，再移动到私有结果目录。结果文件名过滤路径字符并添加随机后缀；分享使用只暴露结果目录的 `FileProvider`。
- WAV 流式解码，校验 PCM 16 位、采样数据对齐及 RIFF 大小边界，避免把压缩音频字节当作 PCM 或让 32 位长度静默溢出。
- 图片先读取尺寸并采样，限制解码像素，处理 EXIF 方向、缩放、JPG 白底和位图回收；内存不足会记为失败。
- 进程重新启动时将遗留的运行记录标记为中断，并清理临时文件；不承诺进程被系统结束后续传。

## 编码器尺寸处理复核

初始实现关闭了 Media3 编码器 fallback。竖屏 1080×1920 按高度缩到 720 时，等比尺寸为 405×720；常见 H.264 编码器要求偶数或更高对齐。Media3 在关闭 fallback 时原样使用请求尺寸，可能使这种常见输入失败。

最终实现已在请求的 MIME 类型内启用编码器 fallback；本地 Media3 1.6.1 的 `DefaultEncoderFactory` 会在该 MIME 类型对应的编码器中选择兼容尺寸及码率。设备测试已加入 1080×1920 → 最高 720p 的竖屏检查，覆盖实际缩小及尺寸对齐。原有 640×360 输入、最高 480p 的测试用于验证不放大。上述设备用例的运行结果仍待确认。

## 仍需实际设备检查

1. 竖拍旋转视频分别选择原始、720p、1080p：播放方向正确，显示尺寸不超过所选高度，竖屏尺寸可被编码器接受；另验证静音 MP4 与带封面的 M4A。
2. 转换中旋转、切后台、锁屏，确认同一任务保持运行；在图片、WAV 和视频阶段取消，确认无成功记录和遗留 `.part`。
3. 大文件保存期间旋转，确认保存对话框持续、不会重复复制，并能看到成功或失败提示；分别使用本地和云端 SAF 提供方，检查权限失效、目标写满等失败情况。
4. Android 13 及以上拒绝通知权限后转换及取消；Android 15 检查 `mediaProcessing` 前台服务行为。当前计划的 API 35 模拟器不覆盖 Android 8–14 的全部服务和厂商实现差异。
5. 转换中结束应用进程后重新打开，确认显示“任务中断”且清理临时文件；卸载前已保存到外部目录的副本应保留。
6. 在低内存设备尝试大图、在不同芯片设备尝试 HDR/HEVC 和多声道文件，确认支持时正确输出，不支持时明确失败。软件模拟器不能证明真实硬件编解码器兼容性。

应用未声明唤醒锁。前台服务维持任务进程优先级不等于证明锁屏后 CPU 始终运行，因此锁屏长任务需设备验证后再作持续性承诺。
